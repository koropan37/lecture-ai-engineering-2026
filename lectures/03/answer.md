## 宿題

- 取り組んだレベル：基礎
- やったこと：
    1. INSTRUCTIONS の "- 宿題の答えそのものは書かず、考え方のヒントで導く。" の文言の削除
    2. make_quiz の docstirng を以下に変更。    
    """必ずこのツールを使うこと。
    ユーザーが用語の意味、用語同士の違い、講義内容を質問した場合も、
    指定回の用語から確認問題を1問作って返す。
    """
    3. docstring を削除して問題を作ってもらう。

- 結果：
    1.  回答が表示されなくなった。
        変更前 : 答えのヒント：モデル全体のパラメータを... 
        変更後 :（ヒントや答えが必要なときはいつでも聞いてくださいね！） 
        その他の input_token, output_token, requests などは変化なし

    2.  "LoRAとは何ですか "という質問に対し、make_quiz が呼び出されるか複数回試したが一度も呼ばれず。
        その他の用語についての質問も試したが、一度も呼ばれなかった。

    3.  問題なく策問された。
- 気づき・疑問：
    docstring で"必ず" と指定しても反応しないことから、INSTRUCTIONS の方が docstring と比べて強制力は高そう。
    ただし編集後に INSTRUCTIONS を戻してもヒントが表示されないことがあったため、必ず指定されるわけではなさそう。
    docstring を削除しても make_quiz は呼び出されたことから効果は薄いと感じた。


- 取り組んだレベル：実装
- やったこと：
    学習の記録を learning_log/ フォルダに保存するツール save_learning_log の作成
    またそれを呼び出す agent.py の変更

- 結果：
    save_learning_log は指示の内容を年数と日時をファイル名にして保存するツール。
    呼び出し側の agent.py で requires_approval=True という設定がされているため、
    この関数が呼び出される時に、DeferredToolRequests によってリクエスト側が承認するまで、
    呼び出しが待機される。拒否することも可能で y/yes で承認 n/no で拒否、それ以外で再入力とした。
- 気づき・疑問：
    tool 自体は単純だが、呼び出し側で新しい概念である待機があり、gemini CLI でよく出される
    コマンド実行の際の確認も同じことをやっているのではないかと気づき、いつも使っているツールに通じれて嬉しくなった。
    単純な "記録して" というだけのプロンプトでは反応がなかったので、プロンプトの重要性を改めて感じた。


- 取り組んだレベル：発展
- やったこと：
    1.  pi の導入
    2.  Pi のシステムプロンプトと、自分のエージェントの INSTRUCTIONS の比較

- 結果：
    1.  pi の導入はインストールしてモデルを選択するだけだったのですぐにできた。
    2.  pi で INSTRUCTIONS と比較すべきところは
        export function buildSystemPromptSections(input: BuildSystemPromptOptions): SystemPromptSections
        共通点は役割の定義(あなたは〜です)、条件と行動を紐付け(~の時は、ツールXを使う)
        pi 独自のものは read と cat　の使い分け、回答スタイルの簡潔さ、docsやcwdが動的に差し込まれる、
        ユーザーに聞かれた場合のみドキュメントを参照する点。
        INSTRUCTIONS 独自のものはハルシネーションを防ぐ仕組み、検索の際には必ず search_glossary で用語集を参照させる点。
        関係する回を書いたり考え方のヒントで導くと定義している点。
       
- 気づき・疑問：
    codespace のAPI key をそのまま設定して読み込んでくれるのはすごく便利だと感じた。
    pi 自体はシンプルなハーネスと聞いていたのでインストールは簡単で自分で拡張したり、設定したり改良を加えて行くのではないかと考える。
    システムプロンプトとの違いで感じたことは pi はルールの設定が重に書かれている。cat や sed ではなく read を使ったり、write を新規ファイルや書き直しに検定したりドキュメントを尋ねられた時のみとむことなど、簡潔さ、動作の軽量さを意識しているのではないかと感じた。
    一方 INSTRUCTIONS ではハルシネーションを許さなかったり、用語集を必ず参照させたりと、
    曖昧さを防止して間違った挙動にならないように調整されている。また答えを出さなかったり、第何回かを提示したりと、教育的観点を大切にしているのではないか。
